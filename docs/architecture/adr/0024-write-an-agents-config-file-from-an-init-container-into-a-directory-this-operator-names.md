# ADR 0024: Write an agent's config file from an init container, into a configuration directory this operator names

> Status: accepted
> Date: 2026-09-06

Append-only: once merged, the body below is not rewritten. A fact later found wrong is corrected in an appended note, not edited out; a revised decision is a new ADR that supersedes this one.

## Context

[ADR 0012](0012-declare-an-agents-tool-set-in-its-definitions-values.md) decided everything about an agent's tool set but one thing, and named the gap: "Not decided here: **which object renders the declaration into a file in the Pod.** It is not secret, so it needs neither a Secret nor ADR 0010's memory copy, and the choice is a mechanism the implementation issue makes." Issue #139 is that issue and this is that decision. Nothing ADR 0012 settled is reopened here.

**Every claim below was read from `gagent` at `fc5fca4`**, the commit that project's checkout carried on 2026-09-06, rather than received.

**The road the rest of this operator's settings travel is closed to a config file's path.** `--agent-tools-image` and the workspace's three settings reach their containers as `GAGENT_*` variables, which is why [ADR 0019](0019-mount-an-agents-tool-tree-from-an-image-this-operator-names.md) and [ADR 0023](0023-run-an-agents-workspace-as-a-second-container-this-operator-names.md) could leave `ENTRYPOINT` and `CMD` to the image. The config file is not one of those settings: `internal/config/config.go:183` reads the path with `fs.GetString("config")` — the flag's own value — and not through the viper the `GAGENT_` prefix and its replacer are set on. So no environment variable names the file, and the two roads left are the ones `internal/config/config.go:371-395` walks: `./gagent.yaml` relative to the working directory, then `os.UserConfigDir()/gagent/config.yaml`.

**The first of those resolves against another project's path, and the second against one this operator can name.** `build/agent.Dockerfile` declares `WORKDIR /home/nonroot` and says why — the base sets the same value, and stating it means a base digest bump cannot move it. That is a guarantee about the image and not about this operator: a path this repository does not own, whose only notice of moving is an agent that starts unpinned. `os.UserConfigDir` reads `$XDG_CONFIG_HOME` where it is absolute and `$HOME/.config` otherwise (Go 1.26, `os/file.go`), so the second road's directory is nameable from the environment — which this operator already writes to both containers.

**The file takes a mode, and no volume the kubelet writes can carry it.** ADR 0012's erratum of 2026-08-27 records the mode: `internal/config/owner_only.go` refuses every mode granting a bit outside the owner, so a group-readable pin file is an agent that does not start. Where a Pod carries an `fsGroup` — this one does, by [ADR 0010](0010-copy-an-agents-credential-into-a-memory-volume-the-pods-own-user-owns.md) — the kubelet ORs group access into every file it writes into such a volume: `k8s.io/kubernetes@v1.34.1:pkg/volume/volume_linux.go:149-179` chmods each file to `info.Mode()|mask` with `mask` of `0660`, or `0440` where the volume is read-only. Both leave a group bit set. This repository already records the behaviour, at `credentialsFileMode` in `internal/controller/agent_statefulset.go`, which is why the credential is copied rather than read from its projection. **So the question is not whether to add an object holding the text; it is what writes the file, because something inside the Pod has to.**

**What a wrong pin does was left unmeasured by ADR 0012 and is measured here.** That ADR's consequence says a pin naming a tool the image does not carry is "refused or ignored, and which of the two is not measured here". It is ignored: `internal/tool/registry.go:184-196` checks a pin only for a manifest it loaded, so a pin matching nothing is never consulted. The fatal direction is the other one — a tool the tree carries that the pin set does not name is `unpinned tool`, and the registry refuses to load. A declaration is therefore the whole of what an agent accepts, and a partial one is an agent that does not start.

**`gagent` states its own reason for keeping the pin set out of the environment**, at `internal/config/config.go:216-234`: the config file "is also the only layer holding the pin set's custody — it is mode-checked owner-only, where every tool the agent spawns inherits the whole environment." That reason reaches how this operator carries the text as well as where it lands.

## Decision

**An init container writes the agent's config file, and this operator creates no second API object for it.** The container is `config`, it runs the image `--agent-copy-image` already names, and it writes into an `emptyDir` the agent mounts. A ConfigMap was the alternative and it removes nothing: the measurement above says a mounted file cannot be owner-only in this Pod, so a ConfigMap would still be copied by a container before the agent could read it. It would buy a name to invent, a permission to hold, and an object's lifetime to manage, for a value ADR 0012 records as not secret — which is the ground that ADR gives for refusing "a second object holding the tool set" one layer out.

**The file's text reaches that container in its environment and is part of no command.** A pin is a string this operator does not read, cannot constrain, and receives from a console field; a value interpolated into a command is a value that can stop being one. `ci.md` §Security baseline states that rule for a pipeline's inputs — "pass attacker-controlled input to a command through the environment, never interpolated into the command text" — and an init container's argument list is the same shape of hazard, so it is settled the same way. The variable is set on the writing container alone, so nothing the agent spawns inherits a pin set, which is the custody `gagent` refuses the environment road to keep.

**The directory is `/run/gagent/config`, and the agent is told it as `XDG_CONFIG_HOME`.** The XDG road is taken over the working-directory road because it is the one whose directory this operator names: absolute and this repository's, for the reason ADR 0019 gives `/opt/gagent/tools` — a relative default resolves against a working directory in somebody else's image. `XDG_CONFIG_HOME` is not one of `gagent`'s settings and reaches no viper of its own; it is read by the standard library on the way to the file. The `gagent/config.yaml` beneath it is that project's and not this operator's to choose.

**The file is written owner-only as it is created, under a umask rather than by a mode set afterwards**, so there is no instant at which it is readable by anyone else. `install -m`, which the credential's copy uses, is not reached for here: that command copies files that already exist, and this one writes text that exists only in the environment.

**The volume is a plain `emptyDir` and not the memory-backed one ADR 0010 makes.** That volume answers a rule about key material and a pin set is public — which is the half of ADR 0012's sentence its erratum leaves standing. The mode is the half that does not follow from it, and it is taken.

**The file is the agent's whole configuration and not the pins'.** It is rendered from a struct whose fields are `gagent`'s setting names, so a second key family — a model, a memory path — joins it as a second field rather than as a second file, a second container, or a second volume. Nothing in the container, the volume, the directory or the variable is named for pins.

**It is marshalled and never assembled.** A pin is a foreign string, and the one place such a string can change what a file means is where somebody wrote the file's syntax by hand. Map keys marshal sorted, so one declaration renders one text and an unchanged `Agent` leaves the workload unchanged.

**An `Agent` declaring no tool set builds the workload this operator built before one could be declared** — no volume, no container, no mount and no variable — and one that stops declaring has all four taken back out. That is the shape `--agent-tools-image` and `--agent-workspace-image` already use, arriving here from a field of the spec rather than from this operator's configuration.

**An empty declaration is refused at the API server rather than delivered.** `internal/config/config.go:262-269` refuses a pin section naming no tool, so an empty one is an agent that cannot start; `+kubebuilder:validation:MinProperties=1` is what makes it unwritable. ADR 0012 says an empty pin set and no pin set are different inputs and that only `gagent` decides what either means — it does, and what it decided is that one of them never runs.

## Consequences

Easier: an agent's tool set reaches the agent, so the `WARN tool drift pinning disabled: no pin set configured` that issue #139 was opened on has something to stop saying. A second setting worth declaring is a field on one struct and a key family in one parser, and reaches the same file by the same road.

**Nothing here has been exercised against a cluster, and the acceptance signal has not been observed.** What is verified is what this operator builds, at the integration layer against the Kubernetes 1.36.2 API server, including that a Pod carrying the writing container is admitted by a namespace enforcing PodSecurity `restricted`. The shell that writes the file is run by the check set, in a temporary directory, against the text a declaration renders — which is what says the file arrives owner-only and that a pin closing its own quoting lands as a pin. envtest has no kubelet, so no layer here starts the container, and the e2e suite runs a substitute image that reads no config file. That the log line stops is a claim only a cluster can settle.

**This operator now depends on how `gagent` finds its config file, and that road is not the one its other settings travel.** ADR 0012 already accepted becoming a writer of another project's configuration format; this adds a dependency on that project's *discovery* order, which no environment variable can pin and which fails silently — an agent that does not find the file starts unpinned and logs the absence, exactly as it does today. What would notice is the log line, which is not a thing this operator reads.

**A tool set edited after an agent is constructed does not reach it.** The declaration is written into the `Agent` at construction, and a definition is claimed once. `spec.image` had the same limit until [ADR 0018](0018-keep-the-image-of-an-agent-this-operator-constructed-current-with-its-own-configuration.md), which is the shape a correction would take and the ADR it would extend; what it would have to answer first is which fields of an `Agent` a person may edit, since a written `Agent` and a constructed one carry the same field. It is recorded as an open question rather than answered here.

**Every agent that declares a tool set now runs a second init container**, so its Pod starts one step later and a node that cannot pull `--agent-copy-image` leaves it one container further from starting. That image was already required for the credential, so no deployment gains a dependency.

**The tool set is visible in the Pod's spec.** It is in the `Agent`'s spec already and ADR 0012 records it as not secret, so this moves no boundary; what it means is that `kubectl get pod -o yaml` is a second place a pin set is read from, and a pin set is a statement about what an operator accepted rather than a secret about it.

Ruled out: **a ConfigMap**, which does not remove the container that has to write the file and adds an object, a name and a permission. **A Secret**, which adds all of that and a claim about secrecy ADR 0012 refuses. **The `--config` flag**, which would take `ENTRYPOINT` and `CMD` from the image — ADR 0019's rejection, holding here for the same reason. **`./gagent.yaml` under the image's working directory**, which is a path another project declares; it is stable by that project's own statement, and it is still not this operator's to name. **`install -m`**, which copies a file that exists rather than writing text that does not. **Naming the container, the volume or the variable for pins**, which would make the second key family a second mechanism.

Nothing is superseded. [ADR 0012](0012-declare-an-agents-tool-set-in-its-definitions-values.md) is extended with the mechanism it deferred; ADR 0010 is untouched and is why the mode is owner-only and the volume is not memory-backed; ADR 0019 and ADR 0023 are the shape this follows for a thing the workload carries and no flag names.
